# 自动处理循环设计

## 背景

当前测试版已经支持企微消息采集、待处理队列、手动分类写回、需求入库、知识库问答和自动回复。现有 `poll --watch` 只持续采集消息，仍需要用户在 Codex 会话中触发分类处理。

## 目标

新增测试版自动处理循环，让本机服务可以持续执行：

1. 采集目标群和白名单用户的新文本消息。
2. 读取待处理队列。
3. 用规则自动判断消息类型。
4. 将业务诉求写入需求收集表。
5. 将知识库命中问题写入问答日志并自动回复。
6. 将无关消息忽略，将无法判断消息转待人工判断。

## 处理规则

1. 知识库问答：消息命中知识库标题、关键词或正文中的问题文本时，判断为问答。
2. 需求收集：消息包含明确业务诉求词时，判断为需求，不要求系统使用人员给出研发实现细节。
3. 忽略：系统自动回复提示、闲聊、无意义短句不进入需求或问答。
4. 待人工判断：无法判断是否为业务诉求、规则咨询或无关内容时，不自动回复。

## 命令

新增命令：

```powershell
node src/cli.js auto --watch
node src/cli.js auto --once
```

新增脚本：

```powershell
npm run auto
```

## 运行策略

`auto --watch` 每轮执行一次采集，再处理队列中有限数量的待处理任务。处理条数由 `auto_process_limit` 控制，默认 20。循环间隔沿用 `poll_interval_seconds`。

## 回复格式

企微 CLI 当前只支持文本消息。自动回复会把 Markdown 图片语法转换为普通文本链接，例如：

```text
参考图片：https://example.com/a.png
```

## 验收

1. 自动循环可以持续运行。
2. 知识库命中问题能自动回复。
3. 明确业务诉求能自动写入需求表。
4. 系统提示和闲聊不会重复回复。
5. 待处理队列处理后无残留已判断任务。
